## 风险清单

### P0 — 立即处理

1. **轮换 GitHub 令牌。** 本地 remote URL 曾包含明文 PAT；本轮只完成 URL 清理，无法证明令牌未被其他日志/历史保存。完成标准：旧 token 失效，remote/凭据管理器/CI 均使用新最小权限凭据，secret scanning 无告警。
2. **停止 API 覆盖式发布。** `deploy-push.mjs` 直接创建 blob/tree/commit 并移动远端 `main`，导致本地历史与生产历史脱节，也绕过 PR/CI/分支保护。完成标准：从干净 clone 创建分支，所有发布只通过 PR 合并。
3. **保护 `main` 并启用必需检查。** 当前任何有写权限的凭据都可直接改生产。完成标准：要求 PR、审查、已解决对话和 `Quality Gate`，禁止 force push。

### P1 — 近期处理

1. **轮换/修复 Vercel token。** 当前 API 认证失败，平台状态和回滚能力不可自动审计。
2. **把本轮治理文件合入干净分支并让 CI 首次全绿。** 当前 `.github/workflows/ci.yml` 在远端存在但没有运行记录，且旧内容未执行单测/构建/E2E。
3. **将 PRD 的 3 个确认缺陷转成 Issue。** 包括首页编辑打开空表单、撤销时长文案不一致、批量删除文案低估范围；为每项指定优先级、验收测试和负责人。
4. **制定数据恢复演练。** 当前只有人工 JSON 导出，没有恢复频率、保管要求或旧版本兼容演练。

### P2 — 计划改进

1. 用 Dexie schema version 显式管理后续数据迁移，避免迁移逻辑只靠模块级一次性函数。
2. 为生产 smoke 建立轻量自动检查，并记录版本、路由、PWA 离线和更新证据。
3. 评估 `/patient` 固定壳对深链、多标签页和故障恢复的限制。
4. 清理 `pinyin-pro` 等死依赖、历史日志/截图和临时 QA 脚本，降低仓库噪声。
5. 采集真实移动设备上的 LCP/INP/CLS，而不是只依赖 localhost 性能预算。
