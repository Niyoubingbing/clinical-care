# 2.18.0：床位识别与查房路线分离

日期：2026-09-06。基于 GitHub 2.17.3（a8ff50f），保留原界面和核心待办功能；未采用此前放弃的整站重构。

## 当前规则

- 默认查房配置保持原样，未清空或重新生成用户的路线。
- 床位类型由 `recognizeBed` 计算：单床修正 → 兼容旧强制虚拟名单 → 当前模板解析 → 待确认。
- 识别不到不再等于虚拟床。只有明确指定的虚拟床才受“隐藏虚拟床”影响。
- 默认格式兼容大小写、全角、J4/J04、YZ04、普通床、子床；自定义正则可使用旧捕获组或 ward/mark/bed 命名组。
- `resolveOrder` 只负责位置。完整床号精确指定优先于 J04 等病区通用规则，再优先于基础数字规则；不同标记不串床。
- 混合规则按病区依次套用；全部为完整床号时保留显式跨病区顺序；同一病人只出现一次，未安排的病人稳定追加。
- 单床位置调整按床号而非病人 ID 保存。可以提前配置空床；病人更换不影响位置。
- 基础规则是生成初始路线的工具。打开向导不清空路线；生成或恢复默认需要确认。
- 块拖拽、上下移动、房内前后移动均保留顺序，导入不自动排序；保存排队执行，并拒绝其他页面过时的路线覆盖。

## 兼容与数据安全

不改变 IndexedDB 表结构或病人/待办 ID。应用级迁移在事务内执行，可重试；旧自定义名称床位的显式类型转为单床修正，原查房块保留。

新增 Settings.bedRecognitionVersion / bedTypeOverrides 为可选字段。旧 virtualOverrides 继续兼容；清空病人/待办不会删除床号配置。

旧版 `computeBedType` 仅保留为 2.17 路线成员判断兼容函数；2.18 实际页面及导入使用 `recognizeBed`，不读取旧持久化 bedType 作为唯一依据。

## 一并修复

- 换药待办补齐不再被同日其他类型待办阻止；跨标签并发补齐在事务内查重；非法无限换药周期不再产生死循环。
- 空名单或含坏行的替换式导入不能删掉原名单；所有实际删除都需确认；重复提交、重复床号、库中同名歧义及过期预览会被拒绝。
- JSON 导入验证可选文本字段、重复 ID 和孤立待办，验证失败不替换原数据。
- 保留用户“跟随系统”主题选择，迁移不再强制改成浅色。
- 离线 RSC 数据按稳定路径匹配预缓存，不受查询参数影响，且与 HTML 分开；版本查询不走旧 SW 缓存；安装预缓存失败不能激活不完整的新版本。
- 当前版本来自已运行的构建包，更新失败不再显示“已是最新版本”。
- 换药规则在设置、详情和病人表单使用统一入口与独立弹窗；首页分组/方向/虚拟床控制压缩为紧凑筛选条。

## 验收与边界

本地最终验收：Lint、TypeScript、生产构建通过；22 个逻辑测试文件 / 166 项测试通过，28 项浏览器测试全部通过（含实际断网）。

验收覆盖默认及基础规则、J/YZ 混合床号、跨病区、单床修正、替换病人、刷新、并发保存、迁移、导入安全、换药幂等、小屏布局、无障碍及首次安装后的离线完整操作。

本次没有增加账户、云同步或服务端病人数据存储。花名册仍以姓名匹配，不能可靠区分同名病人；检测到库中同名歧义时要求分别编辑。数据导出仍只含病人/待办，查房路线可单独导出，单床修正仍保存在本机设置中。

回滚：可回滚静态部署，但 2.17 仍按路线判断床型，不能完整理解 2.18 的单床类型修正；因此优先前向修复，回滚后需核对虚拟床显示。Vercel 回滚不会删除或恢复 IndexedDB。
